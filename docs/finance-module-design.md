## 1. 业界调研结论

### 1.1 三大流派与代表项目

| 流派 | 代表项目 | 核心概念 | 对本模块的借鉴点 |
| --- | --- | --- | --- |
| **流水/预算型** | Firefly III（24.5k★，PHP，复式记账）、Actual Budget（28.6k★，信封预算）、ezBookkeeping（5.5k★，轻量记账） | 记录每一笔收支流水，预算控制 | ① Firefly III 的**附件机制**（借据/存单挂到任意记录）② 按账户/类目分组管理 |
| **投资组合型** | Ghostfolio（8.1k★，净资产+持仓+行情）、Wealthfolio（7k★，本地优先）、Maybe Finance（54k★，净资产追踪） | 持仓与净值，组合分析 | ① 总览 Dashboard：净资产曲线 + 资产分布环形图 ② **快照机制**（每日自动记录，构成趋势历史）③ 手动录入为主的隐私理念 |
| **资产负债表型** | 财小蜜（多账户资产整合/XIRR/借贷利息与还款提醒）、WorthTrail（资产+负债总览/标签分组）、招行个人财务管理（现金/活期/定期/股票/基金/债权/国债/理财/债务分类；定期记账：新增存单/到期取款/续存）、家财旺账簿（定期存款到期前 7 日推送本息试算） | **家庭资产负债表**：登记各类资产与负债 → 汇总净资产 | ① **资产分类体系与每类专属字段**（正是用户需求所在）② **到期管理**（存款到期、外借归还）③ 本土分类（定期/活期/理财/贵金属/外借/外债） |

### 1.2 提炼的业界共识（直接进入设计）

1. **总览页标配**：总资产 / 总负债 / 净资产三卡片 + 资产分布环形图 + 净资产趋势曲线（Ghostfolio、Wealthfolio、Maybe、财小蜜完全一致）。
2. **资产分类 + 类型专属字段**：每类资产字段差异大（定期看利率到期、外借看借款人借据），业界一律"预置分类 + 每类独立字段模板"。
3. **到期日历**：定期/理财到期、借贷归还统一进入到期提醒（家财旺：到期前 7 日本息试算；财小蜜：借贷还款提醒）。
4. **附件归档**：Firefly III 将附件作为一级能力挂到任意实体（借据、存单照片、合同扫描件）。
5. **历史快照**：趋势图的数据来源是"定期记录各资产价值"（WorthTrail：自动每日记录；定期存款则按利息累计推算）。
6. **手动录入为主**：自托管/隐私流派共识——不自动连接银行/行情，数据主权优先；行情自动抓取仅作可选增强。

## 2. 模块定位决策

**采用"资产负债表型（资产台账）"为主干**，叠加组合型的总览图表与 Firefly 的附件机制；**不做流水记账**（收支流水/预算属后期可选延伸，不在本模块范围）。

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 领域模型 | 资产记录（asset registry），非交易流水 | 用户需求是"各类资产详情 + 到期 + 归档"，台账模式最贴合 |
| 资产 vs 负债 | 记录分两个方向：**资产**（定期/活期/理财/贵金属/股票/外借债权…）与**负债**（房贷/外债/信用卡…）；总资产−总负债=净资产 | 外借是债权（资产），外债是欠款（负债），业界通行做法（招行分债权/债务两类） |
| 行情获取 | v1 全部手动记录市值；自动行情预留接口不实现 | 零外部依赖原则；隐私流派共识 |
| 分类方式 | 预置分类 + 启用/停用开关，不自定义新建 | 预置已覆盖需求（含"其他"兜底），降低 v1 复杂度；后续版本可放开 |
| 币种 | v1 仅人民币，外币资产以人民币折算登记 | 控制范围；多币种是 v2 候选 |

## 3. 信息架构（二级菜单）

理财模块主色沿用 `--m-finance`（绿色）。

## 4. 资产分类与字段设计（领域模型）

### 4.1 预置分类体系

| 方向 | 分类 | 说明 |
| --- | --- | --- |
| 资产 | 银行定期 | 整存整取存单 |
| 资产 | 银行活期 | 活期/现金/零钱通等活钱 |
| 资产 | 理财产品 | 银行理财/净值型产品 |
| 资产 | 贵金属 | 实物黄金/纸黄金/积存金 |
| 资产 | 股票基金 | 股票、场内外基金、ETF |
| 资产 | 外借（债权） | 借给亲友的钱 |
| 资产 | 国债保险 | 储蓄国债、储蓄型保险（预留） |
| 资产 | 其他资产 | 兜底（收藏品等） |
| 负债 | 房贷 | 按揭余额 |
| 负债 | 外债（欠款） | 向亲友借的钱 |
| 负债 | 信用卡/消费贷 | 待还余额 |
| 负债 | 其他负债 | 兜底 |

### 4.2 通用字段（全分类共有）

`名称`、`方向(资产/负债)`、`分类`、`归属人(家庭成员)`、`机构/交易对手`、`金额`、`开始日期`、`到期日`、`年利率(可空)`、`状态(持有中/已到期/已结清)`、`备注`、`附件(0..n)`、`创建/更新时间`。

### 4.3 分类专属字段模板（新增/编辑弹窗按此动态渲染）

| 分类 | 专属字段 | 自动计算 |
| --- | --- | --- |
| 银行定期 | 银行名称、存入日期、到期日期、存入金额、年利率、存单号、自动转存(是/否) | 期限(月)、到期利息=金额×利率×期限/12、到期本息 |
| 银行活期 | 银行/渠道、当前余额、余额更新日期 | 较上次更新差额 |
| 理财产品 | 产品名称、发行机构、购买金额、起息日、到期日、业绩基准年化、风险等级(R1~R5) | 预计到期收益=金额×基准×天数/365 |
| 贵金属 | 品种(金/银/铂)、形式(实物/纸/积存)、持有数量、成本单价、当前单价 | 当前市值=数量×单价、浮动盈亏 |
| 股票基金 | 标的名称、代码、市场、持仓数量、成本金额、当前市值 | 持仓成本单价、浮动盈亏 |
| **外借（债权）** | **借款人、借出日期、借款金额、约定归还日期、利率(可空=无息)、还款方式(到期一次/分期)、已还金额、借据材料附件、关系备注** | 未还金额=借款−已还、逾期天数 |
| 外债（欠款） | 债权人、借入日期、金额、约定归还日期、利率、已还金额 | 未还金额、逾期天数 |
| 房贷 | 贷款银行、贷款总额、剩余本金、月供、还款日、利率(LPR/固定) | 预计结清月 |
| 信用卡 | 发卡行、账单日、还款日、当前欠款、分期中(是/否) | 距还款日天数 |

> 外借的"关键材料备份归档"：上传借据照片/转账凭证后，附件在详情页与台账行内直接可见（📎 标记），满足"借据归档"需求。

### 4.4 家庭成员与归属人（owner）

家庭场景下各资产的持有人不同（存款在谁名下、股票账户是谁的、外借经谁的手借出），设计如下：

- **轻量成员字典**：`finance_members`（姓名、备注、可空 `user_id` 预留列——M4 多用户时成员可关联系统账号）。成员不建系统登录账号；入口在新增/编辑弹窗的下拉项"＋ 新建成员"与台账工具栏"成员管理"
- **归属人（持有人）**：每笔资产/负债必填，默认"本人"（首位成员）。语义对照：资产=在谁名下；外借=家庭中哪位成员借出；负债=以谁的名义负债
- **与"经办人"区分**：谁录入/维护这条记录，由操作日志中的 `user_id` 承担（详情页操作日志可见），不与归属人混淆——避免引入语义含糊的"责任人"
- **统计能力**：台账按成员筛选；总览环形图三维度并排：**[按分类 | 按成员 | 按机构]**（谁的资产、钱放在哪些机构一目了然；机构维度聚合资产方向，空机构归"未填写机构"，扇区点击跳转台账按机构名搜索）；收益分析（M3a）已实现按成员/分类贡献拆分与月度趋势

### 4.5 通用机制

| 机制 | 规则 |
| --- | --- |
| 状态机 | `持有中` →（到达期日自动）`已到期` →（手动确认）`已结清/已支取/已续存`；外借还清、负债还清同理 |
| 到期提醒 | 到期前 30 天（预告，黄色）/前 7 天（紧急，橙色）/逾期（红色）三级；出现在总览卡片、台账行内、到期日历 |
| 实际收益录入 | 理财产品专属：详情页录入银行 App 显示的**当前累计收益**，后端换算市值（本金+收益）写入 `finance_asset_values` 快照，事件表记录 `interest` 数值；详情页/对比矩阵展示实际年化（累计收益 ÷ 本金 × 365 ÷ 持有天数），与业绩基准同屏对比 |
| 市值历史 | 每次手动更新资产金额/市值即记录一条 `(日期, 价值)` 快照；定期类按利息逐日累计自动生成；趋势图 = 各资产快照按日汇总 |
| 附件 | 通用附件表（文件名、存储路径、类型），存储在 `data/uploads/finance/`；与挂起的"文件存档"模块**无依赖**（理财自带轻量上传） |

### 5.6 收益分析页 `#/finance/analytics`（M3a，已实现）

```
│ 累计已实现收益 │ 近12月已实现 │ 在途预计收益 │ 平均实际年化 │  ← 摘要卡
├────────────────────────────────────────────────┤
│  月度收益趋势柱状图（近12月，负月红柱向下）          │
├───────────────────────┬────────────────────────┤
│ 收益贡献（分类，环形图） │ 收益贡献（成员，环形图）    │
├───────────────────────┴────────────────────────┤
│  收益明细表：日期|资产|分类|归属人|类型|金额|备注      │
```

**收益口径（三类严格区分，不混算）**：

| 口径 | 数据来源 | 归集规则 |
| --- | --- | --- |
| 已实现收益 | ① 理财收益录入增量（interest 事件累计值差分）② 年利率类到期利息（定期/国债/外借，end_date 已过按公式）③ 赎回/支取差额（settle 带实际金额时 = 实际 − 本金 − 已录累计） | 增量按持有天数**区间线性分摊**到各月（整数分守恒，负增量如实记录）；到期利息归 end_date 所在月 |
| 预计在途收益 | holding 且未到期的定期（本金×年利率×月数/12）/理财（业绩基准×天数/365） | 仅合计数，不按月归集 |
| 浮动盈亏 | 贵金属/股票 `pnl_cents`（与对比页 `_FLOATING_CATEGORIES` 约定一致） | 独立展示，不计入已实现 |

**API**：`GET /api/v1/finance/analytics?months=12`（1~24 钳制）。返回 `summary`（累计/近12月/在途/浮动/加权实际年化）、`monthly`（近 N 月序列，含零月）、`by_category` / `by_member`（全历史已实现聚合）、`details`（原始事件粒度倒序，上限 100 条，kind=maturity/interest_input/withdraw_gap）。

**交互**：分类环形图扇区点击跳台账分类筛选；成员环形图跳归属人筛选；明细行点击跳资产详情。月度柱状图含负值时自动切"0 基线居中"模式（正柱绿向上、负柱红向下）。

### 5.7 数据导入导出（M3b · 已实现，v0.5.0）

入口：资产台账页工具栏「导入 / 导出」按钮。核心实现 `backend/app/services/finance_io.py`（仅标准库 json/csv/zipfile）。

**导出三种产物**：

| 产物 | 端点 | 内容 |
| --- | --- | --- |
| CSV 资产列表 | `GET /finance/export?format=csv` | 未删除资产摘要表（UTF-8 BOM，Excel 直开），人工查看用，不做 CSV 导入 |
| JSON 数据备份 | `GET /finance/export?format=json` | 六表全量快照（含软删除行与附件元数据），头部 `{format, version, exported_at, app_version, data}` |
| ZIP 完整备份 | `GET /finance/export?format=json&attachments=1` | manifest.json + attachments/ 附件物理文件；缺失文件仅备元数据并计 warnings |

**导入两种模式**（`POST /finance/import`，multipart：`upload` 备份文件 + `mode`，上限 200MB）：

| 模式 | 行为 | 适用 |
| --- | --- | --- |
| merge（合并） | 按主键 upsert（categories 按 code，其余按 id），可恢复软删除行 | 同源备份恢复/合并 |
| restore（清空恢复） | 先清空理财六表（删 assets 触发 CASCADE）与附件目录，再全量恢复到备份点 | 整机迁移/备份点回滚；前端红色警示 + 二次确认弹窗 |

**导入实现约定**：

1. 导入顺序按外键依赖：categories → members → assets → values → events → attachments；整个导入单事务，格式级错误回滚。
2. 列名白名单（`_TABLE_COLUMNS`）防手改备份注入额外列名；缺失的 created_at/updated_at 补当前本地时间。
3. user_id 跨机处理：members 可空 → 失效置 NULL；assets/events 不可空 → 归导入操作者。
4. 行级失败（外键引用缺失/唯一约束冲突/必填字段缺失）跳过并计入 skipped 报告，不中断整体事务。
5. 附件物理文件在 DB 事务 commit 成功后处理：restore 先清空附件目录再提取；ZIP 条目做路径穿越（zip slip）防护，物理文件失败仅告警不回滚 DB。
6. 前端弹窗（`pages/finance/io.js`）：导出为三选项下载列表；导入为文件选择（.json/.zip）+ 模式单选，restore 展示危险警示并经 confirmModal 确认；结果按表展示导入行数、跳过明细与附件恢复数，关闭弹窗自动刷新台账。
