## 1. 业界调研结论

### 1.1 国内银行理财平台（上银理财 / 邮储理财 / 浙银理财"理财超市"）

各银行官网理财列表的**标准对比维度**高度一致：

| 维度 | 具体内容 |
| --- | --- |
| 产品业绩 | 近1月年化 / 近1年年化 / 成立以来年化 / **业绩比较基准**（区间形式，如 2.25%~3.05%） |
| 期限 | 持有 N 天后可赎回 / 封闭期 / 定期开放 |
| 风险等级 | R1~R5（PR1~PR5）官方分级 |
| 起购金额 | 0.01 元 / 1 元 / 1000 元 |
| 产品类型 | 自营 / 代销、固收 / 混合 |

**收益对比要点**（银行客服专业建议）：同一风险等级下对比业绩基准区间、过往实际收益贴近基准中枢的程度、费率成本。

### 1.2 国内比价平台（融360 / 和讯 / 新浪财经计算器）

- **定期存款比价**：输入期限（如 3 年）→ 按利率从高到低列出各银行 → 交叉表格（银行 × 期限）
- **存款计算器**（新浪财经/建行等）：金额 × 年利率 × 期限 → 到期本息试算；短期按实际天数折算 `利息 ≈ 金额 × 年利率 ÷ 360 × 天数`
- 核心思路：**"同样一笔钱，放不同地方各得多少"** 的模拟试算

### 1.3 国际组合对比工具（Portfolio Visualizer / FundVisualizer）

- Portfolio Visualizer：**并排组合对比**（最多 3 个组合 vs 基准）——指标对比表（CAGR / 波动率 / 最大回撤 / Sharpe / Sortino）+ 增长曲线叠加
- Capital Group **FundVisualizer**（业界产品对比标杆）：多产品并排卡片、统一指标表、压力测试、含 contributions/withdrawals 的情景模拟、watchlist
- 共识交互：**多选 → 并排表格（行=维度、列=产品）→ 统一化指标**（不同类型产品的原始指标不可直接比，必须换算成统一口径）

### 1.4 开源项目（Ghostfolio / Firefly III / Portfolio Performance）

- Ghostfolio（8.1k★）：持仓聚合 + 分配分析，**无专门"产品对比"功能**
- Portfolio Performance：业绩 vs 基准对比（组合层面）
- **结论**：开源界没有现成的"理财产品对比"组件；业界通用做法是 **comparison matrix（对比矩阵）+ 统一指标换算**，无外部库可引入，按本系统零依赖原则自研即可（前端成本主要在表格渲染，本系统 ui.js 组件已可覆盖）

### 1.5 提炼的业界共识（进入设计）

1. **并排对比矩阵**是标准形态：行=维度、列=产品，产品名做列头
2. **不同类产品必须换算统一口径才可比**（定期看利率、理财看业绩基准 → 统一为"年化收益率"）
3. **收益模拟器**（同金额同期限试算）是家庭决策刚需（比价平台标配）
4. 风险等级（R1~R5）与流动性（距到期天数）必须进入对比（银行理财超市共识）
5. 对比数量 2~6 个为宜（PV 限 3 组合，FundVisualizer 2~4）

## 2. 功能定位与决策

| 决策项 | 结论 | 理由 |
| --- | --- | --- |
| 菜单位置 | 新增二级菜单 Tab「对比分析」，置于「到期日历」与「收益分析」之间 | 用户明确要求新子菜单；原「收益分析」保留 M3 占位 |
| 对比对象 | 台账中任意 **资产类** 资产（定期/活期/理财/贵金属/股票/外借/国债保险/其他），2~6 个 | 家庭真实场景是"这笔钱放定期还是买理财"，跨类对比才有价值；负债无"收益"概念，不参与 |
| 对比篮子 | 前端 localStorage 持久化（`fa_compare_ids`），无后端状态 | 对比是临时决策上下文，不产生业务数据；M4 多群组时无需迁移 |
| 统一收益指标 | **统一年化收益率**（后端计算） | 业界共识：定期=annual_rate、理财=extra.base_rate（业绩基准近似年化）、借贷=annual_rate；股票/贵金属等浮动收益类不适用（显示"—"） |
| 模拟器 | 输入金额 + 期限天数 → 各产品按统一年化率试算并排对比 | 比价平台计算器思路；单利公式 `金额 × 年化率 × 天数 / 365` 与后端 wealth 公式口径一致 |
| 后端 API | 新增 1 个只读端点 `GET /finance/assets/compare` | 年化统一/模拟计算放后端（单一事实源），前端纯展示 |

## 3. 对比维度设计（对比矩阵行定义）

### 3.1 维度分组

| 分组 | 维度 | 取值来源 | 说明 |
| --- | --- | --- | --- |
| **基本信息** | 分类 | category_name | 带 12 分类标签色 |
| | 机构 | institution | — |
| | 金额 | amount_cents | 表格金额格式 |
| | 归属人 | holder_name | — |
| | 起始日期 | start_date | — |
| | 到期日期 | end_date | 活期等无到期显示"—" |
| | 期限 | computed.days/months | 定期显示"12 个月"，理财显示"365 天" |
| | 当前状态 | effective_status | 持有中/已到期/临近到期…标签 |
| **收益能力** | **统一年化收益率** | 后端归一 | 定期/借贷取 annual_rate；理财取 extra.base_rate；其余"—" |
| | 利率/基准原文 | 分类专属字段 | 定期"年利率 3.5%"、理财"业绩基准 2.25%~3.05%"（extra 原样） |
| | 实际年化 | computed.actual_annualized_rate | M2d：录入实际收益后派生（累计收益÷本金×365÷持有天数），未录入显示"—" |
| | 实际累计收益 | computed.actual_interest_cents | M2d：最近一次录入的累计收益金额，与业绩基准同屏对比"跑没跑赢" |
| | 预计到期收益 | computed.est_interest_cents | 已有计算结果 |
| | 到期本息 | computed.maturity_cents | 本金+预计收益 |
| **风险** | 风险等级 | extra.risk_level（理财） | R1~R5 标签着色（其余类无此字段显示"—"） |
| | 风险提示 | 派生 | 浮动收益类标注"收益浮动，不保本" |
| **流动性** | 距到期天数 | 派生 | 复用 dueText 逻辑；已过期显示"已到期 N 天" |
| | 附件材料数 | attachment_count | 回形针线性图标 + N 个 |

### 3.2 统一年化收益率规则（后端 `compare_assets` 计算）

| 分类 | 年化收益率 | 依据 |
| --- | --- | --- |
| 银行定期 | `annual_rate` | 即为年化利率 |
| 理财产品 | `extra.base_rate` | 业绩基准年化（近似年化收益，标注"基准"） |
| 外借（债权）/ 外债 | `annual_rate` | 约定利率；无息为 null → "—" |
| 国债保险 | `annual_rate` | 储蓄国债票面利率 |
| 银行活期 / 贵金属 / 股票基金 / 其他资产 | null → "—" | 浮动或无固定收益概念，不做静态年化（业界不把活期/股票折成年化对比，避免误导） |

> 注：股票/贵金属的浮动盈亏在总览与详情页已有呈现，对比矩阵中不强行年化，风险分组提示"收益浮动"。

### 4.2 台账入口（资产多选加入对比）

- 台账行首列复选框为**统一勾选模型（v0.9.2 更新）**：勾选结果同时驱动「加入对比（N）」与「批量删除（N）」两个工具栏按钮（实时计数、0 时禁用）；资产与负债行均可勾选（负债可删），点「加入对比」时自动只取资产、负债跳过并 toast「N 项负债不支持对比已自动跳过」
- 点击「加入对比（N）」写入 localStorage 并 toast「已加入 N 个资产」，成功后跳转对比页
- 行内轻操作「对比」ghost 按钮（复选框之外的快捷入口）
- 对比页内「＋ 添加资产」：弹窗内多选列表（复用资产筛选：分类下拉 + 搜索），确认后合并进篮子

### 4.3 交互细节

- 篮子数量上限 6：超限时 toast「最多对比 6 个产品」
- 篮子内资产被删除/结清后：对比接口对失效 id 静默跳过，并在篮子卡片上显示「已删除」角标
- 对比矩阵列宽自适应，产品 >4 时横向滚动（表格容器 overflow-x: auto）
- 「行=维度」的表格在 768px 以下降级为逐产品卡片（每张卡片列出该产品全维度）

## 5. API 设计（后端新增 1 个只读端点）

### `GET /api/v1/finance/assets/compare?ids=1,4,7`

**权限**：默认用户；**入参**：`ids` 逗号分隔的资产 id（最多 6，超出取前 6）

**响应** `data`:

```json
{
  "items": [
    {
      "id": 1,
      "name": "工商银行定期",
      "category": "fixed_deposit",
      "category_name": "银行定期",
      "institution": "工商银行",
      "amount_cents": 10000000,
      "holder_name": "默认成员",
      "start_date": "2026-01-15",
      "end_date": "2027-01-15",
      "period_label": "12 个月",
      "status": "holding",
      "rate_label": "年利率 3.50%",
      "annualized_rate": 3.5,
      "annualized_note": null,
      "actual_interest_cents": null,
      "actual_annualized_rate": null,
      "est_interest_cents": 350000,
      "maturity_cents": 10350000,
      "risk_level": null,
      "risk_label": null,
      "days_to_due": 89,
      "due_label": "89 天后到期",
      "attachment_count": 2,
      "floating": false
    }
  ],
  "simulate": null
}
```

字段规则：
- `annualized_rate`：统一年化收益率（3.2 节规则），不可比为 null
- `annualized_note`：理财类为 `"业绩基准"`（前端显示 `2.80%（基准）`）
- `rate_label`：利率原文（按分类拼：`年利率 3.5%` / `业绩基准 2.8%` / `约定利率 5%`）
- `floating`：浮动收益类标识（活期/贵金属/股票/其他资产）
- `due_label`：到期描述（复用日历 due_text 逻辑）
- 删除/失效 id 静默跳过；`items` 为空时 `code=0` + 空数组（前端显示空状态）

### 模拟计算（纯前端，基于 compare 返回的 annualized_rate）

`模拟收益(分) = round(金额分 × annualized_rate ÷ 100 × 天数 ÷ 365)`

> 模拟不调用后端（无新端点）：对比页实时改金额/天数即时重算，体验零延迟；公式与后端 wealth 计算口径一致。

## 6. 技术实现要点

### 6.1 后端（finance.py + api/v1/finance.py）

- `compare_assets(conn, ids)`：复用 `_decorate`（category_name/holder_name/attachment_count）+ `effective_status` + `compute`；新增 `_annualized_rate(asset)` 归一方法

- 新文件 `compare.js`：篮子管理（localStorage 读写 + 失效过滤）+ 对比矩阵渲染 + 模拟器（input 防抖 300ms）+ barChart 复用

- `ledger.js`：行复选框 + 工具栏「加入对比（N）」+ 行内「对比」按钮
- `main.css`：对比矩阵样式（列头 sticky、分组行、滚动容器）、篮子卡片、模拟器行内输入
- `common.js`：新增 `RISK_LABELS`（R1~R5 中文映射 + 颜色档）、`addToCompare/removeCompare/getCompareIds`（localStorage 封装）
